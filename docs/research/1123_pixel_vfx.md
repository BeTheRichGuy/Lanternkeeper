# 1123 픽셀 VFX 리서치 - "단순해 보인다"를 어떻게 넘을 것인가

작성: 2026-11-23 / 대상: Idle ARPG (Unity 6 URP 2D, 월드는 오프스크린 RT에 정수배 줌으로 그린 뒤 present 카메라로 화면에 블릿, HDR+Bloom, Light2D 사용)
문제 정의: 현재 VFX = PixelLab 플립북 약 72x76px, 8프레임, 가는 선, 2~3색, 링/점 위주 -> 약해 보임.

## 0. 조사 한계 (먼저 읽을 것)

- 웹 검색 도구가 개발자 1차 자료(GDC 영상, 포스트모템 본문)를 거의 못 가져왔다. 아래에서 **[출처]** 표시는 실제로 열어 본 페이지에서 확인한 사실, **[기억]** 은 조사자의 일반 지식(검증 못 함), **[미확인]** 은 확인 못 한 것이다.
- 확인된 1차 출처: Dead Cells 아트 딥다이브(Game Developer), Octopath UE 인터뷰 요약, Children of Morta 아트 기사(TechRaptor), Graveyard Keeper 그래픽 이펙트 글, Unity URP 2D Pixel Perfect 문서, Vlambeer 화면 흔들림 인용(infovore), 포럼의 Unity 저해상 렌더 논의.
- 따라서 "게임별 비교"는 확정 사실과 추정을 분리해 적었고, 3~4장의 수치는 업계 관행 + 우리 해상도에 맞춘 **제안값**이지 출처 수치가 아니다.

## 1. 게임별 정리

표기: 방식(H=손 프레임, P=파티클, S=셰이더, 하이브리드) / 해상도 / 블렌딩 / 조명 / 왜곡 / 비책.

### Dead Cells (Motion Twin)
- 캐릭터: 3D 모델+스켈레톤을 3ds Max에서 키프레임 -> 보간 -> 픽셀 셰이더로 렌더. 단순 애니는 손작업. [출처: Steam 개발자 답변 및 wnhub 요약 - 검색 스니펫 수준]
- 색: 적/투사체/스펠은 "높은 채도·대비·밝기"로 위협을 먼저 읽히게 한다. 배경은 그레이스케일 + 그라디언트 맵으로 바이옴 색을 바꾼다. [출처: gamedeveloper Dead Cells 딥다이브]
- 파티클은 공기 밀도(안개/먼지)와 전경 구름에 쓰이고, 노멀맵(손으로 포토샵에서 그림)과 함께 "현대적" 인상의 두 축이라고 직접 언급. 노멀맵은 자동 생성기가 너무 납작/엠보스해서 손으로 그림. [출처 동일]
- 스펠/타격 FX가 손 프레임인지 파티클인지, 가산 합성/왜곡 셰이더 사용 여부: 해당 글에 없음. [기억] Heaps(Haxe) 엔진에서 가산 글로우+열 왜곡을 쓴다고 알려져 있으나 [미확인].
- 교훈: FX 자체보다 "채도·밝기 우선순위 규칙"이 가독성을 만든다.

### Hyper Light Drifter (Heart Machine)
- 480x270 디스플레이 해상도 [출처: 검색 요약]. 글로우/블룸 질감은 팬 논의에서 "블룸"이라 하나 개발자 확인 없음 [미확인].
- [기억] GameMaker. 스프라이트 위에 레이어된 확대 글로우 스프라이트와 강한 색 대비(청록/마젠타/백색 코어)로 에너지 느낌.
- 교훈: 제한된 팔레트 안에서 "네온 하이라이트 색 1~2개를 FX 전용으로 예약".

### Children of Morta (Dead Mage)
- 프레임 단위 손 애니 + 손 페인팅 + 현대식 라이팅. 픽셀 애니를 HD로 업스케일해 라이팅 해상도를 일반 2D 수준으로 올렸고, 픽셀화된 라이트 대신 **고해상도 동적 라이트**를 의도적으로 선택. [출처: TechRaptor]
- 우리와 같은 결: 월드는 픽셀, 라이트/블룸은 고해상도 레이어. 단, 우리는 월드 전체를 저해상 RT에 그리므로 라이트도 저해상이 되는 점이 다르다(5장에서 대응).

### Blasphemous 1/2 (The Game Kitchen)
- Unity. 애니는 "픽셀 단위 순수 손작업"을 표방 [출처: 검색 요약]. VFX/피 표현 구현 방식: [미확인]. [기억] 피·종교적 이펙트는 큰 손 프레임 + 화면 플래시 + 강한 적/검정 대비.
- 교훈: 고어 톤은 "큰 실루엣 + 극단적 색 대비(검정 배경에 진홍)"로 해결.

### Eastward (Pixpil)
- 자체 엔진 Maoi(MOAI 기반), 일반 deferred shading으로 라이트를 많이 둔다. "2D 시점의 3D 게임"이라 발언. [출처: Game Developer/Red Bull 검색 요약]
- 교훈: 스프라이트 이펙트마다 라이트를 같이 붙여 환경을 물들이는 것이 입체감의 핵심.

### Octopath Traveler / HD-2D (Acquire, UE4)
- 전투 이펙트가 처음엔 부족해 보여서 **VFX와 함께 포인트 라이트를 추가**했다. [출처: Unreal Engine 개발자 인터뷰 검색 요약]
- 블룸/DOF/틸트시프트 사용 여부: 해당 요약에 없음. [기억] 틸트시프트 DOF+블룸+고해상도 3D 파티클 이펙트가 HD-2D의 특징 [미확인].
- 교훈: 이펙트가 약해 보일 때 먼저 하는 일은 "빛을 더하는 것".

### Sea of Stars (Sabotage)
- Unity, 스프라이트에 실시간 라이트/그림자, 낮밤 순환(달빛). [출처: 2026 스페인어 기사 요약, 세부는 확인 못 함]
- VFX 파이프라인 자세히: [미확인]. [기억] 스프라이트 손 프레임 + 파티클 + 라이트 조합.

### Halls of Torment (Chasing Carrots)
- 90년대 후반 "프리렌더 레트로" 룩. 엔진은 Godot 쇼케이스에 올라 있음 [출처: godotengine.org 검색 결과]. 이펙트 구현: [미확인].
- 교훈: 대량 적 군집에서도 읽히려면 스펠은 크고 단순한 실루엣+높은 명도.

### Vampire Survivors / Brotato
- [미확인] 조사 못 함. [기억] 극단적으로 단순한 스프라이트지만 화면 가득한 개수, 히트 플래시, 데미지 숫자, 보석 반짝임, 화면 흔들림이 "보상감"을 만든다. 정교한 FX보다 "수량과 반응"으로 승부.

- 대시 시 약 4프레임 정지 + 미세 화면 흔들림, 착지 먼지 파티클 [출처: GMTK 자막 2차 인용, 정확한 수치 미검증].
- Noel Berry의 "Remaking Celeste's lighting" 글은 403으로 못 읽음 [미확인].
- 교훈: 작은 파티클 몇 개 + 정지 프레임 + 흔들림의 조합이 "손맛".

- 교훈(개념): 이펙트가 "픽셀 단위로 물질처럼 움직일 때" 가장 고급스럽다. 우리 구조에서는 불꽃/재 파티클이 이 방향.

### Vlambeer (게임 필 일반)
- 카메라를 조준 반대로 6px 반동, 화면 흔들림 값에 4를 더하고 빠르게 감쇠. [출처: infovore가 인용한 RPS 인터뷰]. 즉 흔들림은 "몇 픽셀"이며 지수 감쇠.

### Graveyard Keeper (Unity 픽셀 라이팅 사례)
- Unity 기본 라이트 + 스프라이트별 노멀맵(4방향 칠한 이미지를 스크립트로 합성), LUT 10종으로 시간대/구역 색보정, 그림자는 스프라이트를 버텍스 셰이더로 회전. [출처: Game Developer]
- 우리에게 직접 쓸 것: LUT(팔레트 변환), 노멀맵 응답은 선택.

### 일반 Unity URP 정보
- URP 2D Pixel Perfect Camera는 Upscale Render Texture(Point / Retro AA) 모드를 제공. [출처: Unity 문서]. 슬라이더식 Render Scale은 쌍선형 업스케일 문제가 있어 저해상 RT + 포인트 블릿이 정석. [출처: Unity 포럼]
- 팔레트 양자화/디더 후처리 에셋이 이미 다수(DitherFx, DitherDown, QuickDither 등). [출처: 검색]
- 파티클: RT 렌더 중 Size over Lifetime 지터(WontFix 보고) [출처: Unity Issue Tracker 검색 결과]. 서브픽셀 지터 해법 자료는 못 찾음 -> 5장에서 자체 설계.

## 2. 픽셀 VFX가 고급스러워 보이게 하는 원칙

(출처 표기 없는 것은 업계 관행 + 조사자 판단. 수치는 제안값.)

### 2.1 형태 언어
1. **링/점 금지, 덩어리+꼬리**: 약해 보이는 1순위 원인. 에너지는 "굵은 코어 + 가늘어지는 꼬리 + 튀는 파편" 3요소. 가는 1px 선은 배경 텍스처와 섞여 사라진다.
2. **굵기 최소 3~4px(1x 기준), 코어는 6px 이상**. 영웅 48px 기준 주요 스킬 이펙트는 영웅 키의 0.8~2배.
3. **비대칭**: 완벽한 원/대칭은 인공적. 불꽃 혀, 번개 가지, 얼음 파편은 불규칙한 길이와 방향.
4. **외곽선 대신 값(value) 대비**: 이펙트에 어두운 외곽선을 두르지 말고 가장 어두운 램프색을 가장자리에 쓴다(배경이 밝을 때만 1px 어두운 외곽 허용).

### 2.2 타이밍 (예상-임팩트-소멸)
- **예상(anticipation) 1~2프레임(40~80ms)**: 수축/모임/그림자. 작지만 이것이 있어야 임팩트가 커 보인다.
- **임팩트 1~2프레임 최대 크기+순백/최고 명도, 그 프레임은 오래 유지(홀드 60~100ms)**. 8프레임 균등 재생 금지.
- **소멸은 길고 부드럽게**: 크기는 줄고, 색은 램프를 따라 어두워지고(흰->노랑->주황->빨강->검붉은 재), 파편만 남는다. 전체 400~700ms.
- 프레임 레이트는 가변: 임팩트 직후 60ms/프레임, 중반 90ms, 꼬리 130ms (ease-out). 균일 12fps 플립북이 "싸 보이는" 두 번째 이유.
- 스미어 프레임: 빠른 동작(검격)은 "프레임 1~2장짜리 호 모양 번짐"으로 표현. 중간 보간 프레임이 아니라 한 장의 길고 가는 호.

### 2.3 색 램프
- **뜨거운 흰 코어**: 코어는 항상 거의 흰색(HDR에서 값 > 1로 블룸 유발), 바깥으로 갈수록 채도 높은 중간색 -> 어두운 가장자리.
- 램프는 5~6단계, **색상(hue)이 단계마다 이동**(예: 불 = 흰-담황-주황-적-자주 검정). 명도만 바꾸는 단색 램프는 심심하다.
- 배경 대비: 이펙트 가장자리 색은 배경보다 어둡거나 훨씬 밝게. 우리 맵이 어둡고 붉은 지옥 톤이면 FX는 "밝고 채도 높은 차가운색/흰색"이 훨씬 잘 읽힌다(Dead Cells의 위협 채도 규칙 [출처]).

### 2.4 레이어링 (고급감의 실체)
한 이펙트 = 최소 6개 레이어: ① 코어(밝은 형태) ② 글로우(가산, 블러) ③ 파티클(불티/먼지) ④ 파편/잔해(물리적으로 튐) ⑤ 바닥 데칼(그을음/얼음 얼룩/피) ⑥ 라이트(Light2D, 주변을 물들임) + ⑦ 카메라 반응(흔들림/히트스톱/왜곡). Octopath가 VFX에 포인트 라이트를 추가해서 보강한 것 [출처]이 이 구조의 확증.

### 2.5 이차 운동·잔향
- 파편은 중력/바운스(바닥 1~2회), 불티는 위로 흔들리며 소멸, 연기는 느리게 확장.
- 임팩트 후 0.1~0.3초 뒤에 **후속 반응**(불씨가 날리고, 잔불이 깜박이는 데칼). "끝났는데도 조금 더 있다"가 고급감.

### 2.6 히트스톱/카메라
- 히트스톱: 일반 타격 30~50ms, 크리티컬/폭발 80~100ms (Celeste 대시 4프레임 정지 [출처 2차]). 정지 중 이펙트 스프라이트는 정지, **글로우/라이트는 계속 숨쉬게**.
- 흔들림: 픽셀 단위 정수 오프셋(1~3px), 지수 감쇠(Vlambeer 방식 [출처]). 서브픽셀 흔들림은 픽셀 아트에서 번져 보이므로 정수로 스냅.
- 방치형 특성상 화면에서 동시 다발 타격이 많아 **흔들림/히트스톱은 "큰 사건"에만** 사용, 일반 타격은 이펙트와 플래시로.

### 2.7 해상도 규칙
- 한 화면에서 이펙트 픽셀 크기는 월드 픽셀과 **동일 그리드**일 때 "일체감", 고해상도 글로우는 "빛"일 때만 허용. Children of Morta는 라이트만 고해상도로 [출처]. 즉 **형태는 픽셀 그리드, 빛은 부드러움**이 안전한 분할.

## 3. 권장 하이브리드 구조 (우리 게임용 제안값)

기준: 영웅 ~48px, 월드 RT는 정수 줌. 모든 크기는 "월드 RT 1x 픽셀" 기준.

### 3.1 역할 분담
| 요소 | 방식 | 이유 |
|---|---|---|
| 코어/형태(검격 호, 불덩이, 얼음 창) | 플립북(손 또는 PixelLab) + 셰이더 램프 매핑 | 형태가 브랜드 정체성, 램프를 데이터로 분리하면 속성 변주 5종을 한 시트로 |
| 글로우 | 프로시저럴(가산 스프라이트 + HDR 값) | 플립북에 구우면 가산/블룸 반응 약함 |

### 3.5 파티클 예산
- 동시 활성: 화면 전체 상한 600~800(방치형 군집 전투를 감안). 이펙트 1개당 일반 타격 6~10개, 스킬 20~40개, 궁극 80~120개.
- LOD: 한 프레임에 같은 속성 타격이 8개 넘으면 후속 이펙트는 파티클/글로우 생략, 코어만(Vampire Survivors류 [기억]에서 알려진 "수량 > 개별 품질" 문제 회피).
- 모든 파티클은 1x 픽셀 정수 크기(1,2,3px)만 허용, 위치 스냅(5.1).

### 3.6 플립북 개편 지침 (PixelLab 생성물 개선)
- 8프레임 균등 -> **가변 프레임 타임**으로 재생(데이터에 프레임별 ms 추가). 비용 0.
- 임팩트 프레임 복제 홀드, 예상 2프레임 추가(총 10~12프레임).

- 프레임이 거칠면 `vfx_workbench`로 램프 리맵(같은 형태, 속성별 색)으로 5속성 대량 생산. 형태는 속성 공용, 색/파티클/라이트로 구분(만든 에셋 재활용 원칙과 일치).

## 5. Unity URP 2D 구현 메모

### 5.1 픽셀 스냅 파티클/이펙트
- 가장 안전한 방식: **이펙트를 월드 RT 안에 그린다**(이미 그렇게 하고 있음). RT가 정수 줌이므로 모든 픽셀이 같은 격자. 파티클 크기가 1x 픽셀 정수가 아니면 서브픽셀 경계가 포인트 샘플링에서 깜박인다(파티클 지터 이슈는 Unity Issue Tracker에 WontFix로 보고됨 [출처]).
- 위치 스냅: 파티클 렌더 셰이더 버텍스 단계에서 `worldPos = floor(worldPos * PPU + 0.5) / PPU`(PPU = 월드 RT 1유닛당 픽셀). 크기도 `max(1, round(size*PPU))/PPU`로 양자화. 회전 파티클은 회전을 끄거나 90도 단위만(회전한 1px 점은 안티앨리어싱처럼 번짐).
- 텍스처: Point 필터, 밉맵 끔, `Pixels Per Unit` 일관, 아틀라스 패딩 2px.
- Size over Lifetime은 연속값 대신 **계단형 커브**(예: 4단계)로 지터 방지.
- 카메라 흔들림: 흔들림 오프셋을 PPU 단위로 라운딩.

### 5.2 셰이더 VFX를 아트 해상도로 그리고 팔레트/램프 적용
- 글로우/에너지 형태를 프로시저럴 쿼드로 그리되 **월드 RT에 그리면 자동으로 픽셀화**. 별도 저해상 RT가 필요 없다.
- 램프 매핑 셰이더: 이펙트 스프라이트의 알파/그레이스케일을 "에너지 e"로 보고 `color = tex2D(_Ramp, float2(e, elementRow))`. HDR이면 코어에서 `color.rgb *= intensity`(코어 단계만 >1). 한 셰이더 + 램프 텍스처 5행(속성 5종) = 플립북 한 벌로 5속성.
- 디더링: 글로우 경계를 부드러운 그라디언트 대신 **Bayer 4x4 디더 임계값**으로 `step(bayer, e)`. 월드 RT 픽셀 좌표 기준이라 스냅되고 "픽셀 아트다운 글로우"가 된다. 블룸은 후속 패스가 처리.
- 팔레트 양자화: 전체 화면 팔레트 강제는 이펙트 색을 죽이므로 비추천. 대신 **월드는 기존 팔레트 유지, FX 레이어만 램프 텍스처로 이미 양자화(램프 6색)**. 필요시 LUT 1장(Graveyard Keeper 방식 [출처])으로 present 단계 색보정.
- 외부 후처리 에셋(DitherFx, DitherDown 등 [출처])은 전체 화면 디더가 필요할 때만 참고. 우리 구조에서는 자체 present 셰이더에 몇 줄 추가하는 편이 가볍다.

### 5.3 왜곡/열기 패스 (present 단계)
- 현재: 월드 RT -> present 카메라로 화면에 블릿. 여기에 **왜곡 맵**을 적용한다.
  1. 월드 RT와 같은 해상도의 **Distortion RT**(RG16 또는 RGBA32, 단 RG = 오프셋 벡터, 0.5 = 무변위)를 둔다.
  2. 충격파/열기 이펙트는 이 RT에 별도 레이어(Layer "Distort")로 그림: 파문 링의 노말 같은 방향 벡터 이미지(플립북 또는 프로시저럴 링 + 노이즈).
  3. present 셰이더에서 `uv' = uv + (tex2D(_Distort, uv).rg - 0.5) * strength / worldRTSize`로 월드 RT를 샘플링. 월드 RT 샘플러는 Point.
- **픽셀 격자 유지**: 오프셋을 **정수 텍셀**로 반올림(`round(offset*size)/size`)해서 샘플링하면 픽셀이 번지지 않고 "픽셀이 밀리는" 왜곡이 된다. 최대 변위 2~4텍셀(너무 크면 노이즈처럼 깨짐). 부드러운 왜곡이 필요하면 present가 이미 화면 해상도이므로 최종 해상도에서 서브텍셀 변위도 가능(Octopath/HD-2D식 "HD 효과", 단 픽셀 번짐 감수).
- 용도: 폭발 충격파(링 두께 6~10텍셀, 0.35s), 불 위 열기(위로 흐르는 노이즈, 지속), 공허 렌즈(중심으로 수렴), 보스 등장 파문. 일반 타격엔 쓰지 않는다.
- 비용: 풀스크린 1패스 + Distortion RT 작은 해상도(월드 RT 크기)라 모바일에서도 저렴.

### 5.4 가산 합성 + HDR 블룸 임계값
- 현재 HDR+Bloom ON(카메라 HDR, 지난 커밋에서 복구). 조정 제안:
  - 블룸 임계값(Threshold) 1.0 (선형) 근처, Soft Knee 0.5. 월드 일반 스프라이트는 값 <1 이어야 번지지 않는다 -> **FX 코어만 HDR 값 >1**(불 3.0, 번개 4.0, 프로스트 2.0, 부패 1.4, 공허 코어 2.5 / 테두리 2.0).
  - 강도(Intensity) 0.6~0.9, Scatter 0.6~0.7(넓게 퍼지는 은은한 글로우). 클램프 1000 이상.
  - 가산 글로우 스프라이트: `Blend One One`, 알파가 아닌 컬러에 HDR 곱. 어두운 배경에서는 효과가 크고 밝은 배경에서는 약하므로 **배경이 밝은 막(모래 막 등)은 가산 대신 알파+밝은 코어** 혼합.
  - 블룸은 월드 RT가 아닌 어디서 걸리는지 확인: 월드 RT가 8비트 LDR이면 HDR 값이 잘린다. **월드 RT는 R11G11B10 또는 ARGBHalf 포맷**이어야 블룸이 present 이전/이후 어디서든 동작. (포맷은 현재 설정 확인 필요 [미확인])
  - 블룸이 저해상 RT 위에서 걸리면 블룸 자체가 블록 모양. 가능하면 **블룸은 present 단계(화면 해상도)에서 적용**해 부드러운 빛을 얻고 월드는 픽셀로 유지(Children of Morta의 "고해상도 라이트" 철학 [출처]).
- Light2D: 이펙트에 짧은 수명 라이트를 붙이되 한 프레임에 활성 라이트 수 상한(예: 8). 라이트 텍스처는 저해상 RT에서 계산되므로 경계가 계단질 수 있다 -> 필요하면 라이트에 "양자화(3~4단계)" 셰이더로 톤 계단을 의도적으로 만든다(픽셀 느낌).

### 5.5 성능
- 파티클 800개 + 라이트 8개 + 왜곡 1패스는 PC 기준 문제 없음. 모바일 타깃이면 파티클 300으로 절반, 라이트 4개.
- 데칼은 Tilemap/스프라이트 풀링, 최대 60개, 오래된 것부터 페이드.

## 6. 우선순위 로드맵 (비용 대비 효과 순)
1. **램프 셰이더 + HDR 코어 + 글로우 가산** (기존 플립북 재활용, 하루 단위). 체감 효과 최대.
2. **가변 프레임 타임 + 임팩트 홀드 + 예상 프레임** (데이터 변경만).
3. **이펙트별 Light2D + 파티클 3종(불티/파편/연기)** 템플릿화.
4. **정수 스냅 파티클 셰이더 + 계단 커브**.
5. **지면 데칼 + 잔향**.
6. **present 왜곡 패스** (궁극/보스/폭발에만).
7. 광역/궁극 대형 이펙트(120~256px) 신규 제작: 이 항목만 새 에셋이 필요(이유: 현재 72px 시트는 광역 규모를 커버 못 함). 별도 묶음으로.
